# Bugs

List of current bugs or correctness issues. Also an area for me to keep my rambling where what I want to add is not clear.

- [8-22-2026] A mix that lands behind a standing queue leaves no visible way to it when the player is open. `InstantMixSheet._mix` raises the "Added N tracks" message with its "Open" action through `shellMessengerProvider` (`discovery/discovery_actions.dart` around 110-121), and `AdaptiveShell` is what renders it - but the sheet is raised over the player, which is an opaque route over the shell, so the snackbar is drawn in a subtree the player covers and is excluded from the semantics tree entirely. Since nothing is pushed and nothing on screen changes, that message is the *only* affordance the mix leaves, so from the player a mix appears to do nothing. `instant_mix_test.dart` does not catch it: it asserts the message on the notifier ("read off that rather than found on a screen this host has none of"), which is exactly the half that works. `discovery.spec.ts:13` is the test that does catch it, and it has been red in CI since 44c66a1. The fix is a decision about where an app-level message belongs: rendering it above the router rather than inside the shell is the honest answer, and picking a messenger per caller is not.

- [8-22-2026] A settings search result lands on the section but not on the setting. `settings_screen.dart:135` answers a result with `context.go(WaxRoute.settingsSection(entry.section))`, which carries no setting id, so arriving scrolls nowhere - you land at the top of a long section with the setting you searched for somewhere below the fold. It reads as "search found nothing" for anything past the first screenful, and on web the row is not even in the semantics tree, because the viewport clips it. This only became visible when a Playback row was added above Replay gain in 44c66a1 and pushed it out of view, which is what `settings.spec.ts:13` has been failing on since. The section body is one eagerly-built `SliverToBoxAdapter`, so the rows exist and the missing half is only the scroll: carry the setting id in the location and `ensureVisible` it on arrival. Every row already has a `SemanticsIds.setting(id)` to aim at, but no `GlobalKey`, so the fix has to give the rows something to be found by.

- [8-22-2026] Embedded covert art (manual) for files can be of unknown dimensions. need to make sure things dont break when trying to display those of unexpected size/dimension.

- [8-1-2026] Casting a fresh session from the device picker while local audio plays stops nothing locally: the picker creates the remote session without ending local playback, and the deck bar's precedence keeps the local face over the remote one (device_picker.dart around 313-356, precedence in deck_bar_host.dart around 80-91). Needs Connect's transfer semantics before deciding what "start there" should do to the local engine.

- [8-1-2026] Casting while radio plays transfers a dead item session: mirrorSessionId never clears when radio takes the engine, so the picker (reachable via the settings screen during radio) offers a transfer of a session whose queue the engine no longer plays (connect_controller.dart around 91-99). Same Connect-semantics dependency.

- [8-1-2026] A routed set-rate from another device is silently reset at every gapless boundary: adopt() re-applies the locally configured speed, overwriting the rate the remote controller set (playback_session.dart adopt path). Whether the routed rate should persist across boundaries is a Connect-semantics decision.
