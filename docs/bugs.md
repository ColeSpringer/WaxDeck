# Bugs

List of current bugs or correctness issues.

- [8-4-2026] `review-queue.spec.ts` decides whichever entry sorts first, not its own. It waits for its seeded row to exist, then presses `j` (which selects row 0) and `e`, so on the shared stack any entry another worker opened - `uploads.spec.ts` creates them - is what gets decided, and the poll for `as-is` times out on an entry still pending. Seen once in four runs on 2026-08-04. The spec needs to move the cursor onto its own row rather than assuming position, or filter the queue down to it first.

- [8-4-2026] `typeInto` verifies the DOM and not the app, so a form can submit with a field the helper reported as filled. It types into the `<input>` Flutter's semantics layer renders and retries until `toHaveValue` matches; that assertion passes while the Flutter framework's own controller is still empty, and the submit then fails the field's validator. Five specs flaked on it in one run on macOS (`first-run`, `music-search`, `playback-switch`, `playlists`, `settings`), on a different field each time (username once, confirm-password the next) with no page errors, all green on retry - which is why CI's two retries have been hiding it and local runs, which have none, see it. Two candidates, neither confirmed: the keystrokes reach the element but Flutter's engine drops them while it is mid-frame, or a semantics update replaces the element between the type and the read so the assertion inspects a stale node the framework no longer listens to. The fix in either case is for the helper to assert an app-visible consequence of the text - the field's own error clearing, a control the value enables - and to re-locate the input between attempts rather than holding one handle across the retry (helpers.ts around 9-24).

- [8-4-2026] The admin console draws no section list at the e2e viewport, so `admin-ops.spec.ts:280` ("an exported archive imports back through the backups screen") cannot reach Backups and fails reproducibly. The page snapshot has the shell nav with "Admin console" active and the dashboard rendered - and no `admin-section-*` row anywhere, nor the dashboard's own compact section list, which `dashboard_screen.dart` draws only when `hasSidebar` is false. So the size class reads as sidebar (compact list suppressed) while `AdminConsole`'s `_SectionList` is absent from the semantics tree either way. Verified against `d193196` with P24 stashed, so it predates that phase; every other admin-ops test passes. Start at `admin_console.dart` around 189-209 and whether a 224-wide `ListView` inside the console `Row` is being laid out at zero width or simply not painted at 1280x720.

- [8-4-2026] `connect.spec.ts:75` ("a session mirrors to the server and relays remote control") fails reproducibly: clicking the session row in the expanded player reports "Element is outside of the viewport" after Playwright has already scrolled it into view. The semantics node resolves ("Alpha Song, on WaxDeck client") and the click still lands nowhere, which is the shape of a node whose reported rect and painted rect disagree. Verified against `d193196` with P24 stashed, so it predates that phase; the other connect tests pass.

- [8-2-2026] `TestCueSplitEndToEnd` is flaky under full-suite load: seen once as `pieces kept the virtual pids` at tools_integration_test.go around 536, then passing in isolation and across four consecutive full runs of `internal/api`, so it is rare rather than fixed. The task itself had already been asserted `done` with two `resultPids` two lines earlier, and the failing read is the `/library/items` listing right after, which still answered the pre-split virtual carvings. So the gap is between the split committing and the listing reflecting it, not the split failing. Two candidates, neither confirmed: the drain helper returns when `DrainToolTasks` reports no more work, which may be ahead of the catalog change the replacement lands through; or the listing read is served from a generation the split has not yet bumped. Worth reproducing under `-count` with `-race` before picking one - a fix aimed at the wrong half would just move the window.

- [8-1-2026] Casting a fresh session from the device picker while local audio plays stops nothing locally: the picker creates the remote session without ending local playback, and the deck bar's precedence keeps the local face over the remote one (device_picker.dart around 313-356, precedence in deck_bar_host.dart around 80-91). Needs ADR-0008's transfer semantics before deciding what "start there" should do to the local engine.

- [8-1-2026] Casting while radio plays transfers a dead item session: mirrorSessionId never clears when radio takes the engine, so the picker (reachable via the settings screen during radio) offers a transfer of a session whose queue the engine no longer plays (connect_controller.dart around 91-99). Same ADR-0008 dependency.

- [8-1-2026] A routed set-rate from another device is silently reset at every gapless boundary: adopt() re-applies the locally configured speed, overwriting the rate the remote controller set (playback_session.dart adopt path). Whether the routed rate should persist across boundaries is a Connect-semantics decision.
