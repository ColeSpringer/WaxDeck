# waxdeck_api_gen (EXPERIMENTAL)
First-party REST API for WaxDeck: the self-hosted player, library manager,
and metadata completer for music, podcasts, and audiobooks.

Current scope: health, an authentication stub, library browse and search,
item detail, artwork, lyrics, play-info, playback state (resume), listen
session ingest, and library scanning. The shapes (keyset pagination, typed
PIDs, the structured error model, relative media URLs) are load-bearing
from day one.

Conventions:
- All endpoints live under `/api/v1` (this document's `servers` entry).
- Item identifiers (`pid`) are type-prefixed ULIDs (`tr-` track, `al-` album,
  `ar-` artist, `pc-` podcast, `ep-` episode, `bk-` audiobook, `jb-` job).
- List endpoints use opaque keyset cursors (`cursor` in, `nextCursor` out),
  never offsets.
- Errors are always the `Error` schema. `code` is a stable machine-readable
  string; currently defined codes: `invalid-request`, `unauthenticated`,
  `forbidden`, `not-found`, `conflict`, `internal`, `stream-stale` (a
  stream URL no longer matches the file on disk; re-request play-info),
  and `catalog-maintenance` (the catalog is temporarily handed to a
  maintenance operation; retry shortly). New codes may appear; clients
  must treat unknown codes as opaque.
- Media URLs returned by the API (e.g. `PlayInfo.url`) are relative to the
  server origin, the same origin that serves this API and the web UI.
